Android System Architecture & Interface Design

AlbumCanvas — Dynamic Live Wallpaper & Ambient Music Experience

An Android application built with Kotlin and Jetpack Compose that hooks into system media playback to dynamically generate ambient, album-reactive wallpapers and Material You home screen widgets.

Role Android Developer & UI/UX Designer
Core Technologies Kotlin, Jetpack Compose, Material 3, AndroidX MediaSession, Palette API
Status Complete & Open Source
Repository github.com/DarsheelShokeen/AlbumCanvas ↗

1. Project Introduction

AlbumCanvas was conceived as an exploration into deeply contextual, atmospheric interfaces for Android. While modern operating systems feature Material You dynamic theming based on a static wallpaper, AlbumCanvas inverts this relationship: it lets the user's active auditory environment shape the entire visual atmosphere of their device in real time.

Whenever a track plays on Spotify, Apple Music, YouTube Music, or any compliant media player, AlbumCanvas intercepts the media metadata, extracts the high-resolution album artwork, computes a balanced 6-tone color palette, and synthesizes dynamic wallpapers and widgets with ultra-low battery overhead.

2. The Problem Being Addressed

Most Android customization apps that attempt to display music artwork suffer from severe structural drawbacks:

  • High Battery Drain: Continual canvas redraw loops in legacy `WallpaperService` exhaust GPU cycles and drain battery life.
  • Poor Contrast & Legibility: Displaying raw square album covers on phone screens clashes with desktop app icons and notification text.
  • Inflexible Notification Listeners: Legacy tools rely on brittle accessibility services rather than the standardized AndroidX `MediaSessionManager` pipeline.

3. Project Objectives & Design Philosophy

"Interface elements should not fight with user content; they should emerge naturally from it."

The guiding philosophy for AlbumCanvas was strict Swiss minimalism applied to mobile motion design. Key criteria included:

  • Zero Perceptible Latency: Track transitions should crossfade gracefully within 300ms of playback change.
  • Automatic Text Scrimming: Contrast calculation using WCAG luminance metrics to ensure home screen icon labels remain perfectly legible regardless of album brightness.
  • Native Jetpack Compose UI: Clean declarative architecture eliminating boilerplate XML views.

4. Technical Architecture

The architecture is structured around four decoupled modules:

  1. MediaSession Listener: A background service observing active `MediaController` callbacks and emitting Kotlin Coroutine `StateFlow` updates upon playback state changes.
  2. Palette Extraction Engine: Asynchronously processes album artwork bitmaps off the main thread with `AndroidX Palette`, extracting dominant, vibrant, muted, and dark saturated swatches.
  3. Wallpaper Render Pipeline: Custom `WallpaperService` that implements an OpenGL / RenderScript blur pass and dynamic mesh gradient shaders.
  4. Glance Widget Layer: Modern home screen widgets built with AndroidX Glance, offering playback controls, track progression, and album art presentation.

5. Challenges and Solutions

Challenge: Memory Leaks with Bitmap Caching

Streaming high-resolution album artwork during rapid track scrubbing could trigger OutOfMemory (OOM) exceptions.

Solution: Implemented an LRU in-memory bitmap cache with downsampling during initial decode, ensuring bitmap memory never exceeds 32MB regardless of playlist duration.

Challenge: Lock Screen vs. Home Screen Separation

Android 13+ introduced stricter wallpaper dispatching policies between lock screen and home screen surfaces.

Solution: Leveraged `WallpaperManager.FLAG_SYSTEM` and `FLAG_LOCK` routing to allow users to isolate dynamic music visuals exclusively to their chosen surface.
