Smart Flood Alert — Urban Water Level Telemetry & Rapid Warning Pipeline

An end-to-end IoT hardware and cloud alerting platform engineered to detect rising water levels in vulnerable urban lowlands and trigger instant emergency broadcasts via WhatsApp and real-time dashboards.

Role Full-Stack IoT & Backend Engineer
Core Technologies ESP32 (C++), FC-28 Water Sensor, Python / FastAPI, Meta Cloud API, Chart.js
Status Deployed & Open Source
Repository github.com/DarsheelShokeen/Smart-Flood-Alert ↗

1. Project Introduction

In many fast-growing cities, severe monsoon rains cause localized flash flooding in underpasses, subways, and low-lying residential sectors within minutes. Traditional municipal monitoring systems are sparse, expensive, and centralized, leaving commuters and residents vulnerable during sudden cloudbursts.

Smart Flood Alert was designed to solve this with a low-cost, decentralized hardware sensing node coupled to an ultra-fast telemetry backend that delivers immediate warnings directly to smartphones via WhatsApp — the primary communication channel used by citizens in India.

2. The Problem Being Addressed

  • Lag in Disaster Dispatches: Traditional flood alerts rely on regional TV bulletins or municipal websites with 30–60 minute latency.
  • Sensor Reliability: Outdoor submersible sensors degrade rapidly due to silt, chemical corrosion, and electrical fluctuations.
  • Friction of Standalone Apps: Citizens rarely keep specialized disaster management apps installed until it is already too late.

3. Project Objectives & System Design

"Emergency notifications must meet people where they already are — immediately, with zero friction."

The guiding technical criteria were:

  • Under-5-Second Alert Propagation: From physical water detection to smartphone vibration within 5 seconds.
  • Triple Redundancy Thresholds: Distinguishing between minor puddles (NORMAL), hazardous accumulation (WARNING), and critical inundation (CRITICAL).
  • Low-Power Edge Execution: Deep-sleep cycle management on the ESP32 microcontroller to enable solar battery autonomy.

4. Technical Architecture

The system comprises three synchronized tiers:

  1. Edge Sensing Node: An ESP32 microcontroller interfaced with an FC-28 resistive moisture and liquid level probe. Code written in C++ (Arduino framework) samples ADC pins at 50Hz, applies a moving-median filter to eliminate wave noise, and transmits telemetry packets over Wi-Fi/4G.
  2. FastAPI Ingestion Gateway: A high-throughput Python FastAPI service receiving JSON telemetry payloads, validating cryptographic tokens, updating rolling time-series records, and evaluating threshold breach triggers.
  3. Meta Cloud WhatsApp Dispatcher: When water exceeds critical thresholds for more than 3 consecutive samples, the backend initiates Meta Cloud API webhooks to dispatch emergency evacuation alerts with GPS pinpoints and safety checklists.
  4. Real-time Telemetry Dashboard: Responsive browser cockpit displaying live water level percentages, status pill changes, battery voltage, and historical drainage trend charts.

5. Challenges and Solutions

Challenge: False Positives from Surface Splashing

Passing vehicles or falling raindrops caused brief voltage spikes on the FC-28 sensor pins.

Solution: Implemented a temporal debounce algorithm on the ESP32 that requires 10 consecutive readings above the threshold over a 4-second continuous window before triggering state elevation.

Challenge: Anti-Spam Notification Throttling

Sustained critical flood conditions risked triggering hundred of repetitive WhatsApp messages, consuming API quotas and annoying users.

Solution: Built a dynamic backoff rate-limiter in FastAPI that sends an initial urgent broadcast, followed by hourly delta status digests unless a severe status transition occurs.

6. Current Status & Open Source

Both the hardware firmware (C++), cloud API (FastAPI), and web dashboard are open-sourced under the MIT license with complete circuit schematics and deployment guides.
